# 旅行方案归档与切换规则

这个仓库只运行一个当前旅行网站，同时用 `travel-plans/` 保存过往方案的最小记忆。当前方案是韩国济州岛，代码和正在使用的 Excel 位于仓库根目录。

## 历史方案保存什么

每个历史目的地只保留两个文件：

- `旅行方案.xlsx`：保留当时完整行程、候选、预算和人工结论。
- `PROMPTS.md`：用简短文字记录人数、天数、预算范围、交通偏好、住宿要求和必须保留的决定。

不归档旧网站代码、`state.json`、页面图片、构建产物、`.env`、共享密码或 AI API Key。Excel 的 `.xlsx` 本身已经是压缩格式，不需要再套一层 ZIP；只有将来附件很多时才考虑额外压缩。

## 切换前必须先归档当前方案

例如以后要把韩国切换成杭州、扬州或其他目的地：

1. 先确认当前韩国 Excel 已经包含最新行程和人工结论。
2. 在 `travel-plans/korea/` 保存韩国 Excel。
3. 新建 `travel-plans/korea/PROMPTS.md`，写清人数、天数、预算、住宿、餐饮、交通、重点路线和放弃过什么方案。
4. 提交并合并到 GitHub，确认远端两个文件都能打开。
5. 完成远端验证后，本地不再保留单独的韩国历史资料夹。

## 重做目标方案

1. 从 GitHub 读取目标目的地的 Excel 和 `PROMPTS.md`。
2. 把它们当作历史参考，由 AI 按当前网站架构重新生成方案，不直接恢复旧 `state.json`。
3. 对价格、营业时间、入境要求、交通班次和预订规则重新核实。
4. 将网站标题、数据、Excel 和页面内容整体切换到目标目的地。
5. 执行构建、权限、Excel 和公网访问测试。
6. 通过 GitHub PR 合并，新目的地成为唯一当前网站；本地只保留这个正在运行的项目。

以后可以直接对 AI 说：

```text
请先按照 travel-plans/README.md 归档当前方案，再读取 travel-plans/<目的地拼音>/ 的 Excel 和 PROMPTS.md，把当前网站完整切换到该目的地。重新核实动态信息，测试通过后再发布。
```
