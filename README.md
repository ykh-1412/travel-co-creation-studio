# 济州岛旅行共创台

这是当前正在运行、并同步到 GitHub 的韩国济州岛项目。历史旅行资料统一保存在相邻的 `旅游` 资料库中；当前站点只运行济州岛方案。

## 当前旅行

- 目的地：韩国济州岛
- 人数：6 人
- 时长：3 天 2 晚
- 初版结构：济州市区两晚 + 东线完整日 + 涯月返程半日
- 入境硬约束：按济州免签条件规划国际航班直达济州；不要默认经首尔转韩国国内线也适用
- 交通：岛内公交优先，只在末段接驳、晚班或天气不便时由 6 人分摊短途出租车

具体日期、直达航班、住宿、公交班次、餐厅和动态价格都保持“待确认”。团队后续投递真实链接或文字诉求后，DeepSeek 会整理成候选并写入 Excel。

## 旅行方案档案

GitHub 同时保存已经做过的旅行方案。当前韩国济州岛方案在仓库根目录，历史扬州方案保存在 [`travel-plans/yangzhou`](./travel-plans/yangzhou/)；历史档案只保留 Excel 和精简 Prompt，重新启用时由 AI 按当前架构重做，不直接恢复旧网站数据。完整切换规则见 [`travel-plans/README.md`](./travel-plans/README.md)。

## 数据处理流程

1. 朋友在公网团队页粘贴链接，或直接写旅行诉求。
2. 后台保留原始输入，并拦截本机、局域网和跳转到内网的链接。
3. DeepSeek 根据“韩国济州岛、6 人、3 天 2 晚”的背景拆分地点、攻略或团队需求，并初步估计推荐分、价格依据、优缺点、资料完整度、适合时段和待核实线索。
4. 结构化结果写入 Excel 的投递台账、处理报告、候选决策台和对应分类表。
5. 主电脑可让 DeepSeek 对照完整 Excel 与当前行程再审阅一次；每条结果进入 `AI审阅建议`，只有人工逐条采纳后，允许自动写入的候选字段才会更新。第几天、是否适合团队、是否淘汰等决定始终只作为人工待办，不自动改正式方案。
6. 主电脑在网页或 Excel `行程首页` 定稿，网站自动刷新。

链接若需要登录、验证码或正文无法读取，会明确标记为“需要人工补充”，不会静默丢失，也不会编造事实。
